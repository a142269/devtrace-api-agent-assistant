# 依赖与安全评估（2026-10-18）

本文件记录 DevTrace 依赖漏洞的核查结论、实际暴露面、处置决定和后续跟踪方式。**结论不是"漏洞已修复"**：ChromaDB 的三个高危漏洞在可获取的最新版本中仍无修复版本。

## 1. 结论速览

| 项目 | 结论 |
| --- | --- |
| 受影响组件 | `chromadb==0.5.23`（同时存在于 Python 依赖和 Compose 的 `chromadb/chroma:0.5.23` 镜像） |
| 漏洞数量 | 3 条（2 条 HIGH、1 条 CRITICAL） |
| 是否存在修复版本 | **没有**。OSV 数据显示受影响范围到 `1.5.9`（当前 PyPI 最新版），沿无 `fixed` 事件 |
| 是否升级 | **不升级**。升级到 1.5.9 不能消除漏洞，且是 0.5 → 1.x 的大版本迁移，客户端/服务端/集合 API 都有破坏性变更风险 |
| 是否可以宣称安全 | **不可以**。当前只是"本地单租户演示 + 网络隔离"，不能作为多租户或生产部署 |
| 本轮实际加固 | CI 依赖门禁（只拦有修复版本的漏洞）、部署配置回归测试、隔离边界文档化 |

## 3. DevTrace 的实际暴露面

- Compose 中 `chromadb` 服务**不发布宿主端口**，只加入项目内部网络；`redis`、`developer-sandbox` 同样不发布端口，只有 `devtrace` 映射 8000（本机验证时改用 18002）。
- DevTrace **没有启用 ChromaDB 的认证/授权提供方**（未配置 `CHROMA_SERVER_AUTHN_PROVIDER` 等），因此不处于漏洞描述里"已认证用户 + RBAC"的多租户形态；实际形态是单租户、内部网络、无鉴权的本地演示。
- 这不等于安全：任何能进入该 Docker 网络或连上 Chroma 端口的进程都可以读写全部 collection；而且项目本身没有生产身份、租户和 TLS。
- 数据都是虚构的模拟平台记录，不含真实用户数据或真实凭据。

## 4. 处置决定

1. **保持 `chromadb==0.5.23`，不升级**：升级不能修复漏洞，只增加回归风险。等上游发布修复版本后再评估（届时需要同时升级 Python 包和 `chromadb/chroma` 镜像并重跑检索、记忆与集成测试）。
2. **维持网络隔离**：ChromaDB/Redis/模拟平台不发布宿主端口；新增的回归测试会防止有人误加 `ports`。
3. **明确不做生产承诺**：README 和工程审查继续注明"本地演示、单租户、无真实租户授权"。
4. **生产化时替换或隔离**：若要接真实数据，优先替换为支持租户隔离的方案（如 pgvector、Qdrant），或使用托管 Chroma 并启用其租户隔离与认证；至少需要独立网络、认证、TLS、最小权限凭据和审计。
5. **持续跟踪**：CI 的 `pip-audit` 保留，新增 `developer/audit_gate.py` 作为门禁——**只有存在修复版本的漏洞才阻断构建**；当前三条"无修复版本"会继续以非阻断方式显示，避免 CI 长期变红但无人处理。

## 5. 本轮新增的自动化

- `developer/audit_gate.py`：解析 `pip-audit` JSON，发现 `fix_versions` 非空即失败；缺失报告时跳过并告警。单元测试见 `tests/test_audit_gate.py`。
- `tests/test_deployment_config.py`：断言 ChromaDB/Redis/沙箱不发布宿主端口、只有应用暴露、沙箱健康检查指向 8100、`.env` 同时被 `.gitignore`/`.dockerignore` 排除、镜像以非 root 运行且有健康检查。
- CI：`ruff` 范围纳入新文件；依赖扫描后执行审计门禁。

## 6. 局限与未完成

- 本轮在本机重跑 `pip-audit` 时，PyPI JSON 请求反复停滞，未能生成新的报告。可用的完整扫描是 2026-10-17 **升级前**基线（5 个包 34 条，含旧版 starlette 等）；升级后复扫汇总为 1 个包 3 条，但该次 JSON 未保存；直接依赖扫描保存了 chromadb 的 3 条。本轮已用 OSV 官方数据核对这 3 条"无修复版本"。CI 会在 GitHub 上重新运行完整扫描并由 `audit_gate` 判定；当前目录下没有 `dependency_audit_2026-10-18.json`。
- 用旧报告验证门禁行为：运行 `python -m developer.audit_gate developer/dependency_audit_2026-10-17.json` 会因 30 条"有修复版本"的记录返回 1，并列出 4 条无修复版本的记录作为非阻断提示——说明门禁能区分两类漏洞；升级前的旧报告本来就不应通过当前门禁。
- 没有对 ChromaDB 做渗透测试或利用验证；结论基于版本匹配、配置形态和网络边界。
- 没有评估替代向量库的迁移成本和效果，这是生产化阶段的工作。
