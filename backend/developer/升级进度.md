# DevTrace 升级进度与验证边界

本次升级基于提供的六周方案。以下记录代码实际实现，未完成项不视为已经达到生产级。

## 已实现

- 服务端签发短期 JWT，本地账号使用 PBKDF2 密码摘要；诊断和运行记录从 token 获取身份，不接受客户端自报 `user_id`。登录和聊天通过 Redis 固定窗口限流，CORS 使用配置的来源。
- 同一用户和会话通过 Redis 锁互斥；不同请求冲突返回 409。`Idempotency-Key` 可以重放已完成请求结果，并拒绝同键不同内容。工单另有自己的业务去重。
- 认证诊断根据模拟请求记录添加或跳过密钥权限工具；`diagnosis` 使用成功工具观察生成带来源的结果。这里是有限的规则与模型协作，不是完全开放的假设搜索。
- 文档检索加入小规模 BM25 词法检索、向量检索和 RRF 融合；两路检索在召回时按版本和 active 状态过滤，并提供少量 v2 文档。现有诊断主链路仍固定 v1，尚未实现学习型重排、多 SDK 和完整 v2 场景。
- 固定基线标签已移到独立 JSON，评测记录诊断、证据和工具数量，并区分模型、规则及降级。基线依然与模拟数据共享案例，不能证明泛化能力。
- 现有 CI 加入 Ruff 检查和覆盖率输出；模拟平台默认不映射外部端口。画像更新改为有超时的同步尝试，没有构建可靠队列。
- 使用 SSE 逐条展示计划、行动与观察；前端可以停止当前 HTTP 请求。断开连接会取消执行并释放会话锁，未完成的中间状态并非持久化的取消任务。
- 新增组合案例 `delivery_combo_01`：投递记录提供关联请求 ID，执行器据此追加请求核验；实际观察到 429 后再检索限流文档。两条记录分别形成证据，关联关系不等于证明二者存在因果关系。
- 最近运行按认证用户建立 Redis 索引，保留最多 100 条、有效期 24 小时，接口返回最近 50 条；前端可查看和恢复会话。每轮报告工具耗时、模型 API 调用耗时与服务端返回的 Token 用量；未返回的 Token 显示为未知。
- 区分记录 404、空文档和工具不可用，后两种情况可用同一标识继续重试。运行时间线在工具开始前发送行动事件。

## 实测（2026-10-17，本地 Docker）

- 规则模式 HTTP：30/30 通过；适用根因标注 20/20，证据来源检查 30/30，平均工具调用 2.23 次，中位耗时 73.2 ms。结果来自[原始记录](eval_upgrade_rules_2026-10-17.json)，本地固定数据和规则模式不代表真实模型准确率或生产性能。
- 隔离 Redis 上同会话并发结果为 200 和 409；不同账号读取运行记录返回 404；同幂等键重放获得同一个 run_id。
- 真实 HTTP 流式请求返回 11 个时间线事件与完成事件；断开流时释放锁由自动化测试验证。
- 前端生产构建通过；自动化测试和覆盖率以本次实际执行结果及 CI 为准。

## 尚需完成

- 独立标注的复杂、多原因、异常和安全评测集，四组对照实验及真实模型评测。
- 扩大组合故障与关联记录覆盖，多假设追踪与证据冲突处理；当前覆盖的动态分支有限。
- 持久化任务取消、持久任务队列与审计；现有运行历史仅包含执行完成或等待用户后保存的记录。
- 真实租户授权、身份服务、TLS、密钥轮换、业务数据隔离、生产限流和故障恢复策略。
- 独立检索评测、学习型重排、文档生命周期管理、v2 诊断和依赖漏洞扫描。

通用请求幂等在结果成功写入 Redis 后生效，进程在外部副作用与缓存之间崩溃时不保证恰好一次；不要将它作为生产级事务保证。
