# 开发者平台 API 接入助手：技术栈与工程化审查

审查范围：当前 `EchoMind/developer`、复用的 Python 组件、`EchoMindFrontend` 开发者页、测试和 [evaluation_report.md](evaluation_report.md)。评价“工程级”时区分 **可复现的工程原型** 与 **可接生产数据的服务**。六张参考图给出通用 Agent 十模块清单；其中 MCP 协议、Tree-of-Thought、代码执行、多 Agent 和流式输出是可选路线，不能因为清单中出现就声称本项目已实现。

## 1. 结论

**技术栈对首版模拟场景基本完整，达到可演示、可测试、可复现的工程原型水平；尚未达到直接对外提供真实开发者平台排障服务的生产级要求。** 缺口主要在身份认证和租户权限、会话并发控制、开发者场景专属可观测性、在线评测广度、外部数据安全边界和部署治理。Vue 而非 React 不影响 Agent 能力；用户要求的 ReAct 是行动与观察循环概念，不要求 React 前端框架。

当前最值得准确讲述的设计是：模型负责提出目标与逐步行动，服务端按故障类型强制最小证据链，工具观察决定下一步与证据，失败可追问并跨轮恢复。**它是受约束的 Agent，不是“模型可以自由规划任意工具”的开放式 Agent。**

## 2. 与原项目对照

| 维度 | 原客服 `/chat` | 新开发者 `/developer/chat` | 审查判断 |
| --- | --- | --- | --- |
| 场景和路由 | 细粒度意图识别、主辅 Agent、升级路径 | 单主 Agent；`_kind()` 将问题约束为三类 | 单 Agent 是首版明确边界，不需复制多 Agent |
| 规划/行动 | 原 Agent 工具循环；由模型选择是否检索 | 明确计划步骤、证据要求、行动/观察/恢复 | 新场景更适合展示受约束的多步计划 |
| 工具 | 客服 RAG 工具、工具管理器 | 文档、请求、密钥摘要、投递、工单五工具 | 本地注册工具；未实现 MCP 协议服务 |
| 记忆 | Redis 工作记忆、摘要、ChromaDB 历史/画像 | 复用同一实现，独立键和 collection；额外存计划/运行 | 隔离思路明确；缺真实身份绑定 |
| 检索 | 通用知识库，部分链路支持改写/重排 | 独立 v1 文档库，语义检索后按类别过滤 | 有可追溯文档，尚无正式文档版本生命周期 |
| Skills | 客服按角色/关键词匹配，可通过原接口热加载 | 开发者 Skill 启动时注入模型系统提示 | 具备场景规范，但无开发者专属热加载 |

| UI | 客服聊天与调试页面 | 计划、时间线、工具观察、证据、记忆 | 可展示执行结果；不是实时事件流 |

原项目文档和简历模板含部分宽泛表述，应以对应代码和 [evaluation_report.md](evaluation_report.md) 中实际测量为准；本审查不沿用未经复核的效果指标。

## 3. 对照图片的十模块状态

| 图片模块 | 当前状态 | 代码证据与准确边界 |
| --- | --- | --- |
| 1. 大模型核心 | 已实现，受限 | `AnthropicDecisionModel` 通过兼容接口输出计划与下一行动 JSON；最终答复由成功观察确定性生成 |
| 2. 记忆 | 已实现，演示级 | `MemoryManager` 读 Redis 最近消息/摘要与 ChromaDB 情景记忆/画像；`developer:plan:*` 保存未完计划；知识库是外置知识而非用户记忆 |
| 3. 规划 | 已实现，受约束 | 模型提议目标/工具顺序，执行器保留合法顺序并补齐最小证据链；模型从满足依赖的步骤中选行动；失败最多修订一次；无 Tree-of-Thought |
| 4. 工具调用 | 已实现，非标准协议 | 五个本地工具通过 `MCPToolManager` 注册并执行；没有原生 Function Calling 消息流或 MCP server |
| 5. 执行引擎 | 已实现，限定操作 | 对文档/模拟 HTTP API 查询及 SQLite 工单写入；无 shell、代码执行、文件修改能力，符合本场景最小权限 |
| 6. 观察反馈 | 已实现 | `actions`、`timeline`、`evidence` 存工具结果并传入下一次行动选择；失败不计入成功证据 |
| 7. 状态调度 | 已实现，单实例原型 | 单请求串行循环、最多 5 次工具行动/1 次修订、Redis 跨轮恢复；无分布式队列或同会话锁 |
| 8. 提示词工程 | 已实现，需强化 | 系统提示 + Skill + 用户/记忆/观察拼接，JSON 解析与有限校验；未对外部文本做专门提示注入隔离 |
| 9. 安全权限 | 部分实现 | 工具白名单、常见密钥脱敏、工单明确授权、模拟记录脱敏；`user_id` 可自报，无真实认证/授权 |
| 10. 输出交互 | 已实现，非流式 | 结构化 HTTP 响应与 Vue 计划时间线；没有 SSE/WebSocket 增量推送 |

## 4. 通过的工程基线

以下结论有代码和已运行验证支撑：

1. **模块分离**：原客服、开发者场景、模拟平台、前端各有独立入口；开发者数据使用独立 Redis 命名空间和 ChromaDB collection。
2. **可重复排障**：30 条固定案例覆盖鉴权、限流、Webhook；请求记录、投递记录和文档能够生成稳定证据。
3. **明确失败语义**：缺标识进入 `waiting`；查询失败标为 `failed` 并最多调整一次计划；模型异常返回 `rules_fallback`，不会冒称模型成功。
4. **受控副作用**：读取工具不改数据；工单写入要有用户明确提出或确认，SQLite 唯一键做重试幂等。
5. **可观察的用户输出**：返回 `run_id`、步骤、行动、观察、来源和决策模式；Vue 可展示完整链路。
6. **自动化验证**：77 个 Python 测试通过；另有 30 个固定案例子测试、三类真实配置模型 HTTP 演示、前端构建与一次浏览器联调。它们证明的是本地样例链路，不是线上准确率。
7. **密钥配置基本隔离**：本地 `.env` 保留在工作区并已停止 Git 跟踪；仓库示例配置不含真实密钥。

## 5. 达到生产级前的差距与优先级

| 优先级 | 当前缺口 | 为什么影响工程级交付 | 可验收的改进 |
| --- | --- | --- | --- |
| P0 | 无真正的用户身份认证与租户授权 | `user_id` 是客户端传入；猜到 `run_id` 与相同用户字符串即可尝试读记录 | API 网关/JWT 或会话身份；服务端从身份派生租户 ID；所有运行、计划、工具查询按租户强制过滤，并测试越权 |
| P0 | 真实数据接入安全边界未建立 | 正则脱敏不能覆盖所有凭据；已加入提示注入启发式扫描和观察不可信标记，但仍不是完整防护；ChromaDB 漏洞暂无上游修复 | 结构化字段白名单、密钥检测与拒收、外部文本隔离、最小权限凭据、审计与留存策略；生产数据前替换或隔离向量库 |
| P0 | 同会话并发请求的互斥已实现，但缺少跨实例/多副本的调度 | 已用 Redis 会话锁与 `Idempotency-Key` 覆盖单进程演示；多副本时锁与任务索引仍需 worker 归属 | 多副本场景下按 worker id 隔离任务索引，补充并发/取消/重启恢复测试 |
| P1 | 规划仍受固定证据集合限制 | 模型现在可影响工具顺序和下一行动，但不能提出新调查工具或形成新的证据路径 | 引入带类型的计划 schema、证据充分性判定和可回滚的修订策略，并扩充安全评测 |
| P1 | 开发者场景专属指标和日志不足 | 原 `/monitor` 面向客服主链路，无法直接证明开发者 Agent 的成功率、降级率、工具耗时 | 按 `run_id` 记录规划/工具/恢复/工单事件；Prometheus 指标区分场景、工具和决策模式；日志不含敏感内容 |
| P1 | 在线模型评测覆盖少 | 已有 19 条独立 holdout 在规则与真实模型模式下均 19/19，另有 4 条模型样例，但总样本仍小、只来自一个 provider，规则案例不等同于模型可靠性 | 扩大第三方独立标注集，加入多轮、干扰输入、模型输出异常、注入、工具慢/失败、工单误触发，定期跑真实模型并记录分母、通过标准和成本 |
| P1 | 工具可靠性尚不完整 | 有超时、熔断、缓存，但没有按错误类型区分的安全重试；熔断/缓存仅进程内 | 查询工具用退避与预算重试；写工具只凭幂等键重试；按 4xx/5xx/超时分别处理并测试 |
| P1 | 依赖与部署治理 | 依赖扫描已在 CI 中运行且有审计门禁；但 ChromaDB 三个漏洞无上游修复版本，镜像仍固定 0.5.23，双 Compose 栈仍可能端口冲突 | 上游发布修复后同时升级 Python 包与 `chromadb/chroma` 镜像并重跑检索/记忆/集成测试；统一单一演示 Compose 入口；继续用审计门禁区分"可修复/无修复"漏洞 |
| P2 | 文档版本与证据粒度 | 当前只内置 v1，引用主要是标题和记录 ID，缺文档片段稳定 ID/时间戳 | 文档版本元数据、稳定片段 ID、更新时间与证据哈希；回归测试旧版本 |
| P2 | 界面只在完成后显示时间线 | 模型和工具较慢时看不到正在执行的步骤 | 若演示/产品需要实时反馈，新增 SSE 事件流与断线恢复；保留现有最终运行记录 |
| P2 | 背景画像更新非持久任务 | 进程退出时异步任务可能未完成，失败仅写日志 | 把画像更新放入可靠队列或可重试任务，按 `run_id` 记录结果 |

这些是从**当前项目目标**出发的缺口，不要求首版全部实现。首要顺序是 P0 的身份/数据/并发，其次是场景级可观测性和模型评测。Tree-of-Thought、多 Agent、浏览器自动化、任意代码执行并非此排障助手走向工程级的前置条件。
